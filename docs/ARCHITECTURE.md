# Архитектура «Бар-менеджер AI»

## Цель

Однопользовательское приложение — персональный рабочий ИИ-ассистент бар-менеджера заведений «Оксфорд» и «Современник».

## Компоненты

### PWA frontend

- задачи и статусы;
- Telegram-входящие;
- диалог с помощником;
- вопросы, требующие решения владельца;
- расписание;
- центр уведомлений;
- локальные черновики и офлайн-оболочка.

### Backend API

- единственная доверенная точка доступа к базе и секретам;
- проверка владельца;
- Telegram webhook с секретным заголовком;
- вызов OpenAI Agents SDK;
- будущие API задач, файлов, push и расписания.

### PostgreSQL

Исходные сообщения и история изменений не перезаписываются. Актуальная карточка задачи хранится отдельно от событий, чтобы можно было восстановить, почему и когда агент изменил вывод.

### Telegram

- только бот;
- бот добавляется в выбранные рабочие чаты;
- разрешённые чаты хранятся в белом списке `telegram_chats`;
- пересланные боту личные сообщения обрабатываются как отдельный источник;
- исходный update сохраняется целиком;
- редактирования связываются с исходной записью;
- сомнительная классификация требует проверки владельца.

### ИИ-агент

Первый уровень — один управляющий агент с инструментами приложения. Специализация добавляется только там, где она улучшает качество:

- разбор Telegram;
- задачи и планирование;
- операционный контроль;
- аналитика файлов;
- подготовка отчётов;
- проверка результата.

Модель задаётся переменной `OPENAI_MODEL`, поэтому её можно обновлять без изменения кода. Для оркестрации используется OpenAI Agents SDK.

### Уведомления

- Web Push на установленные устройства;
- резервное сообщение в Telegram для критичных событий;
- предварительное напоминание;
- уведомление в срок;
- повтор при отсутствии реакции;
- журнал доставки в `notification_events`.

## Правила безопасности

1. Секреты никогда не помещаются во frontend или GitHub.
2. Все защищённые API требуют ключ владельца, позднее — полноценную сессию.
3. Telegram webhook проверяет секретный заголовок.
4. Сообщения принимаются только из белого списка чатов.
5. Отправка сообщений, удаление данных, изменение сроков и закрытие важных задач требуют подтверждения.
6. Действия агента записываются в аудит.
7. ИИ не получает всю базу целиком: backend передаёт только релевантный контекст.

## Этапы

1. Опубликованный PWA-прототип.
2. Размещение backend и PostgreSQL.
3. Реальные задачи и синхронизация frontend/backend.
4. Telegram Bot API и белый список чатов.
5. OpenAI Agent с инструментами задач.
6. Web Push и планировщик.
7. Файлы, аналитика и отчёты.
8. Резервное копирование, мониторинг и эксплуатационные тесты.
